# Messenger Mini — семинар 20.10

Учебный клиент на React и TypeScript к готовому серверу. Реализованы все пункты `../task_condition.md`, в том числе редактирование профиля. Код сервера и условие задания не изменены.

## Запуск

Нужны Node.js 20.19+ или 22.12+ и npm. Откройте два терминала в папке `messenger`.

Первый терминал — бэкенд:

```bash
cd server
npm ci
npm start
```

Второй терминал — фронтенд:

```bash
cd frontend
npm ci
npm run dev
```

Откройте <http://127.0.0.1:5173>. Сервер работает на <http://localhost:3001>, Swagger — на <http://localhost:3001/docs>.

В `frontend/.env` уже указаны адреса из задания:

```dotenv
VITE_API_URL=http://localhost:3001
VITE_WS_URL=ws://localhost:3001
```

Для другого адреса можно создать `.env.local` по образцу `.env.example`. После изменения переменных нужно перезапустить Vite.

## Проверка задания вручную

| Пользователь | Телефон | Пароль |
| --- | --- | --- |
| Alex | +79990000000 | 123456 |
| Maria | +79990000001 | 123456 |
| Sam | +79990000002 | 123456 |

1. Без входа откройте `/profile` или `/chat`: приложение перенаправит на `/login`.
2. Введите неверный пароль и проверьте сообщение об ошибке. Затем войдите с тестовыми данными: откроется `/chat` с историей и статусом `connected`.
3. Перезагрузите страницу: токен в `localStorage` сохранит вход.
4. Откройте `/profile`, проверьте никнейм, телефон и описание. Измените никнейм и описание, нажмите «Сохранить», перезагрузите страницу. Изменения сохранятся на сервере.
5. Откройте второй аккаунт в другом браузере или в режиме инкогнито. Обычные вкладки одного браузера используют общий `localStorage`, поэтому для разных пользователей нужны отдельные сеансы.
6. В чате выберите `WebSocket` и отправьте сообщение. Оно сразу появится у всех открытых участников.
7. Выберите `HTTP (Axios POST)` и отправьте ещё одно сообщение. Остальные получат его через WebSocket, у отправителя оно появится один раз. Один submit отправляет сообщение только выбранным способом.
8. Пустые сообщения и строки из пробелов отправить нельзя. После успешной HTTP-отправки поле очищается; при ошибке HTTP текст остаётся для повторной попытки.
9. Остановите бэкенд: статус станет `disconnected`, отправка заблокируется. Запустите сервер и нажмите «Подключиться снова». Если сервер перезапускался, войдите повторно: его токены хранятся только в памяти.
10. Нажмите «Выйти»: токен удалится, защищённые страницы снова будут недоступны.

## Соответствие условиям

| Требование | Реализация |
| --- | --- |
| `/login`, `/profile`, `/chat` | `src/App.tsx`, React Router, перенаправления по наличию токена |
| `POST /auth/login` через Axios | `src/api/authApi.ts` |
| `GET /users/me` через Fetch | `src/api/userApi.ts` |
| `PUT /users/me` через Axios | `updateProfile` в `src/api/userApi.ts` |
| `GET /messages` через Fetch | `src/api/messageApi.ts` |
| `POST /messages` через Axios | `sendMessage` в `src/api/messageApi.ts`, выбор HTTP в чате |
| `message:send`, `message:new` | `src/api/socketClient.ts`, выбор WebSocket в чате |
| Токен в `localStorage` | `getToken`, `setToken`, `clearToken` в `src/helpers/authStorage.ts` |
| `Authorization: Bearer <token>` | `authHeaders` в `src/helpers/http.ts` |
| Токен в WebSocket | `{ type: "message:send", payload: { text, token } }` |
| Ошибки, загрузка, блокировка кнопок | Страницы, `src/helpers/handleError.ts`, `src/helpers/http.ts` |
| Пустой или некорректный JSON | Явный разбор ответа и проверка формы данных |
| Завершение сессии при 401 | `isUnauthorized` и обработчик в `App.tsx` |
| Нет дублей сообщений | Объединение сообщений по `id` в `ChatPage.tsx` |
| Очистка соединения | `disconnect()` при уходе из чата и выходе |

## Что проверено в Swagger

Открыт `/docs`, сверены примеры запросов и ответов всех пяти операций:

- `POST /auth/login`: `{ phone, password }` → `{ token, user }`, статус 200;
- `GET /users/me`: `User` с `id`, `nickname`, `phone`, `bio`;
- `PUT /users/me`: `{ nickname, bio }` → обновлённый `User`;
- `GET /messages`: массив `Message`;
- `POST /messages`: `{ text }` → `Message`, статус 201.

Все защищённые HTTP-операции требуют Bearer-токен. У сообщения есть `id`, `userId`, `author`, `text`, `createdAt`.

Важная особенность выданного сервера: хотя в условии токен назван JWT, сервер выдаёт учебные строки вроде `token-u1`. Клиент не разбирает токен, а передаёт его как есть. Пользователи, изменения профилей, сообщения и активные токены хранятся в памяти сервера и сбрасываются при его перезапуске.

## Как устроен код

```text
frontend/
  src/
    api/          — HTTP-запросы и WebSocket
    components/   — MessageList, MessageInput, ProfileCard
    helpers/      — localStorage, обработка ошибок, разбор HTTP-ответов
    pages/        — LoginPage, ProfilePage, ChatPage
    types.ts      — User и Message, проверки данных сервера
    App.tsx       — состояние авторизации, навигация и маршруты
    main.tsx      — монтирование App в #root
    styles.css    — оформление, в том числе для узких экранов
  tests/          — браузерные проверки
```

Используются функциональные компоненты и обычные хуки: `useState` хранит данные формы и страницы, `useEffect` загружает данные и подписывается на сокет, `useRef` хранит соединение между рендерами. Дополнительного менеджера состояния нет.

HTTP работает по схеме «запрос — ответ». WebSocket держит открытое соединение: после `message:send` сервер рассылает `message:new` всем клиентам. При HTTP-отправке сервер тоже рассылает `message:new`, поэтому список объединяется по `id`: ответ POST и событие не создают две одинаковые записи. История объединяется с уже полученными событиями, чтобы не потерять новые сообщения во время загрузки. При открытии соединения история запрашивается повторно, чтобы покрыть промежуток до подключения сокета.

Кнопка отправки блокируется без `connected`, как требует задание. В режиме WebSocket очистка поля означает передачу текста в открытое соединение; сообщения об ошибках сервера выводятся отдельно. При выходе из чата соединение закрывается.

## Автоматическая проверка

Из папки `frontend`:

```bash
npm run typecheck
npm run build
npx playwright install chromium
npm test
```

Если Google Chrome уже установлен, вместо скачивания Chromium можно выполнить:

```bash
PLAYWRIGHT_CHANNEL=chrome npm test
```

Playwright сам поднимает сервер и клиент, если они ещё не запущены. Проверяются вход, маршруты, перезагрузка, выход, изменение профиля, три одновременных пользователя, отправка обоими способами, отсутствие дублей, 401, ошибки сети, пустой/повреждённый JSON, отключение сокета, получение события во время загрузки истории и мобильный экран. Ошибочные ответы моделируются только в браузерных тестах, исходный сервер не меняется. Тест редактирования профиля восстанавливает исходные поля после проверки.
