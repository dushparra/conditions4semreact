# Messenger Mini
Нужно собрать минимальный клиент для авторизации, просмотра профиля и обмена сообщениями в реальном времени через уже готовый бэкенд; результат — работающий фронт, который покажет вход, профиль и чат для нескольких тестовых пользователей.

## Что уже есть
- API и WebSocket работают на `http://localhost:3001` / `ws://localhost:3001`.
- Swagger UI: `http://localhost:3001/docs` (посмотри схемы и примеры).
- Тестовые пользователи:
  - `+79990000000` / `123456`,
  - `+79990000001` / `123456`,
  - `+79990000002` / `123456`.
- Код бэкенда менять не нужно; используй только клиентские запросы/сокеты.

## Функционал, который нужно покрыть на фронте
1) Авторизация: форма «телефон + пароль» → `POST /auth/login`, сохранить токен, отрисовать страницы профиля/чата.
2) Профиль: `GET /users/me` (показать никнейм (nickname),  телефон (phone), описание (bio)), создать функцию редактирования никнейма и описания профиля  через `PUT /users/me`.
3) Чат: `GET /messages` (история сообщений), `POST /messages` (отправка сообщений).
4) WebSocket: подключиться, слать `message:send`, получать `message:new` в реальном времени.
5) Страницы/экраны:
   - `LoginPage`: телефон, пароль, кнопка входа;
   - `ProfilePage`: никнейм, телефон, описание профиля и кнопка «Сохранить»;
   - `ChatPage`: список сообщений, поле ввода, кнопка отправки, статус сокета.
6) Инструменты: Fetch для GET (`/users/me`, `/messages`), Axios для POST/PUT (`/auth/login`, `/messages`, `PUT /users/me`), базовая обработка ошибок (401, сеть, некорректный JSON / пустой ответ).
7) Swagger: открыть `/docs`, найти эндпоинты логина/профиля/сообщений, сверить схемы запросов/ответов.

## Что нужно сделать (пошагово)

### Шаг 1. Подготовка проекта и каркас `App`
- Создай `.env` или `.env.local` с
  ```
  VITE_API_URL=http://localhost:3001
  VITE_WS_URL=ws://localhost:3001
  ```
- Проверь, что `src/main.tsx` монтирует `App` в `#root`.
- Собери каркас `App.tsx`: необходимо собрать страницы с разделами «Вход», «Профиль», «Чат». Незалогиненному пользователю должен быть доступен только раздел «Вход», при авторизации должен сохраняться `token`. 
- Что такое `token`: JWT (Json Web Token) — ключ аутентификации пользователя. Используется для запросов к защищённым методам API. Этот ключ должен возвращать запрос `POST/auth/login` и нужен для авторизации в остальных запросах/WebSoket. В запросах отправляй как `Authorization: Bearer <token>`, в WebSoket — вместе с текстом в `message:send`.
Показывай «Выйти» при наличии токена, ограничь доступ — без токена доступна только `login`, после логина открывай `chat` и включай `profile`/`chat`.
- Запусти бэкенд (`npm start` в `server`) и клиентскую часть (`npm run dev` в твоём фронте).

### Шаг 2. API-слой и работа с токеном
- Реализовать функции для взаимодействия с token в `src/helpers/authStorage.ts` (`getToken`, `setToken`, `clearToken`). Токен следует положить в `localStorage` после входа (`setToken`), читай при старте (`getToken`), очищай при выходе (`clearToken`).
- Реализовать функции для работы с API:
  - `src/api/authApi.ts`: запрос `POST /auth/login` для авторизации пользователя;
  - `src/api/userApi.ts`: запрос `GET /users/me` для получения информации о профиле во вкладке «Профиль»;
  - `src/api/messageApi.ts`: запрос `GET /messages`, Axios `POST /messages` (text);
  - `src/api/socketClient.ts`: подключение к веб-сокетам, слушать `message:new`, уметь слать `message:send` для получения сообщений в чате.

### Шаг 3. Страница логина (`src/pages/LoginPage.tsx`)
- Создать форму авторизации: телефон, пароль, кнопка «Войти».
- По submit вызывать `POST /auth/login`, сохранять токен через `authStorage`, передавать его в App.
- Показывать ошибки (например, неверный логин/пароль), блокировать кнопку во время загрузки с помощью `handleError.ts`

### Шаг 4. Раздел «Профиль» (`src/pages/ProfilePage.tsx`, `src/components/ProfileCard.tsx`)
- При монтировании вызвать `getProfile` с токеном, отобразить ник, телефон, bio.
- Опционально: поля для редактирования nickname/bio, кнопка «Сохранить» → `PUT /users/me`, обновить состояние.
- Показать состояния загрузки и ошибок.

### Шаг 5. Чат и WebSocket (`src/pages/ChatPage.tsx`, `src/components/MessageList.tsx`, `src/components/MessageInput.tsx`)
- При монтировании: загрузить историю через `getMessages`.
- Подключиться к сокету (`connectSocket(token)`), слушать `message:new`, добавлять в список сообщения от пользователя.
- Форма отправки: при submit вызвать `sendMessage`. Блокировать кнопку, если сокет не `connected`.
- Показать статус сокета («connected»/«disconnected»), ошибки загрузки/отправки.

## Готовые эндпоинты (бэкенд)
- `POST /auth/login` → `{ token, user }`.
- `GET /users/me` → профиль.
- `PUT /users/me` → обновить nickname/bio (опционально).
- `GET /messages` → список сообщений.
- `POST /messages` → создать сообщение.
- WebSocket: `message:send` `{ text, token }` → сервер шлёт `message:new` с новым сообщением.

## Критерии приёмки
- Логин работает, токен сохраняется и используется в запросах.
- Профиль и сообщения загружаются после логина.
- Сообщения отправляются и приходят по веб-сокетам в реальном времени.
- Используются Fetch (GET) и Axios (POST/PUT), ошибки отображаются пользователю.
- Структура кода: API/хелперы отдельно, страницы и компоненты отдельно.
